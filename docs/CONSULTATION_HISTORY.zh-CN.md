# 协商记录

ChatChat 会把完成的协商保存成浏览器里的**私人本地历史**。

## 本地会保存什么？

为了以后能够完整重放一次协商，本地 archive 会保存：

- 用户提案；
- 最终协商报告；
- 每一条结构化 Blackboard 事件；
- 当时参加协商的参与者信息；
- 时间与轮次。

它和公开的兼容性 Proof Pack 不一样。协商历史是给用户自己看的，因此可以在本地保存真实提案和 AI 事件正文；它不会被当作准备公开上传 GitHub 的材料。

## 历史列表显示什么？

列表使用更轻的 summary：

- 提案短预览；
- 日期 / 时间；
- 参与者数量；
- 轮数；
- 事件数量；
- 改口次数；
- 当前立场一致比例；
- 是否仍然保留不同最终立场。

列表不会复制整场模型正文。

## 存在哪里？

浏览器版协商历史保存在当前浏览器 Profile 的 **IndexedDB** 中。

ChatChat 不会把它上传到 ChatChat 服务器。

```text
浏览器 Profile
    ↓
ChatChat IndexedDB
    ├── 协商 summary
    └── 完整协商 archive
```

默认保留最近 **24 场协商**。

## 回放一场旧协商

打开 **协商记录**，选择 **打开回放**。

系统会直接使用 archive 里的结构化事件重建同一套协商剧场：

```text
保存的提案 + report + events
          ↓
只读 Consultation Theater
          ↓
改口轨迹
影响关系
本地 Replay
原始事件 provenance
```

整个 archive replay **不会再次联系任何 AI Provider**。

## 当前协商和历史回放

打开旧记录时，界面会明确显示 **历史回放**。

如果内存里仍然保留当前刚完成的协商，可以点击 **返回当前协商**，不需要重新运行模型。

## 删除记录

每场记录都可以单独删除。

**清空记录** 会删除当前浏览器数据库里保存的全部 ChatChat 协商 archive。

这不会删除 AI Provider 自己网站中保存的聊天记录。

## 隐私边界

Local-first 不代表浏览器本地存储是“绝对秘密保险箱”。如果其他人或软件能够访问同一个本地浏览器 Profile，就可能接触浏览器本地数据。

如果 archive 中包含敏感提案或模型回复，请不要把 archive 文件主动公开。

ChatChat 不会自动上传这些本地历史。
