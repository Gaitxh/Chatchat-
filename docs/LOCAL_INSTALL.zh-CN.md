# 本地安装 · 未签名开发者预览版

本阶段交付预构建浏览器扩展，以及由浏览器承载的独立协商窗口。需要桌面版 Chrome 或 Edge。它不是已签名原生桌面应用、商店发行版本或离线 AI 模型。普通用户无需 Node、Git、Rust、源码仓库或命令行。

English: [Local installation](LOCAL_INSTALL.md).

## 安装预构建包

1. 从维护者取得 `chatchat-<version>-unsigned-developer-preview.zip`，完整解压到会长期保留的固定目录。打开 `START-HERE.html` 阅读双语离线指南。压缩包内包含 `extension/`、文档、`RELEASE-METADATA.json` 和 `SHA256SUMS`。
2. 在用于登录 AI 网站的浏览器个人资料中，打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`。开启**开发者模式**，点击**加载已解压的扩展程序**，选择解压后的 **`extension/`** 文件夹，其中应包含 `manifest.json`。不要选择 ZIP 或上一级文件夹。
3. 在扩展菜单中固定 ChatChat，点击图标打开协商室。独立窗口由浏览器承载，使用该浏览器个人资料，仍需 Chrome/Edge 提供运行环境；它没有独立的原生运行时。
4. 选择 AI 席位，在**同一浏览器个人资料**中到各提供方网站亲自登录。其他 Chrome/Edge 个人资料不会共享登录态。仅在请求时明确授权你选择的网站。站点权限、账号登录和连接就绪是三个独立状态；打开标签页或识别到网站不能证明已就绪。
5. 每场会议使用新的提供方聊天，不把已有私人会话作为会议输入。检查各席位连接状态，完成界面要求的手动登录或连接步骤。平等协商至少选择两个不同来源，再发送一个提案。每个 AI 来源地位平等，没有享有特权的主持人。

本包不会自动安装。如果受管理浏览器禁用了开发者模式或加载已解压扩展，请联系管理员或等待商店发行。不要为本包修改企业策略。

## 本地协调，云端推理

会议协调与历史保存在当前浏览器个人资料中。发送给选定 AI 网站的提示词由其云端处理，适用各提供方的条款及账号要求。本包不包含 AI 账号或离线模型。

不保证任意网站可用。自动就绪检查只接受新出现的、带明确助手身份标记的回复；无法识别时会失败关闭，需要通过高级修复指定正确的回复区域，而不是把页面正文或输入回显当成回答。URL 识别、教学选择器、合成演示、打包校验或成功打开窗口，都不能证明真实提供方已经就绪。合成演示与真实会话应分离。本次打包交付不包含提供方登录测试或真实网站自动化。

## 更新与卸载

**更新或卸载前先导出重要记录**，使用协商室当前提供的记录、回执导出或复制功能，自行保存。导出记录不等于完整恢复能力。历史属于当前浏览器个人资料和扩展 ID，不是自动备份服务。

关闭会议窗口，保留已安装的扩展，使用**原来同一路径**的文件夹和**同一浏览器个人资料**。将新版本内容替换到已有 `extension/` 中，清除旧版多余文件，再在 ChatChat 扩展卡片上点击**重新加载**，以保留已解压扩展 ID 和关联历史。不要从另一个目录加载新副本并期待其继承历史。移动目录、更换个人资料、清除扩展数据或卸载重装都可能破坏历史延续。

卸载时先导出，再在扩展管理页面点击**移除**。ChatChat 不负责迁移或导出各提供方云端的聊天历史。

## 版本信息与校验和

维护者输出目录包含带版本号的 ZIP、`RELEASE-METADATA.json` 和 `SHA256SUMS`。外部校验和覆盖 ZIP 与元数据；ZIP 内部的另一份 `SHA256SUMS` 覆盖其自身以外的全部文件。校验和可发现文件变化，但没有可信来源时不能认证发布者身份。使用已有工具核对校验和是可选项，安装不要求命令行。

元数据记录版本、可取得时的 Git 提交、工作区状态和未签名预览标签。工作区有修改时，文件并不等同于标注的提交；`null`/`unknown` 表示无法取得提交信息。不会主动写入构建时间、机器用户名、本地绝对路径、凭据或账号数据。整个扩展构建都会发行，因此不要把私人资料放进生产资源。

## 仅供维护者

安装项目开发所需环境后运行：

```bash
npm ci
npm run check
npm test
npm run test:package
npm run package:local
npm run check:package
```

`package:local` 使用现有生产扩展构建及验证流程，然后打包至 `dist/local-package/`。如构建已完成，可用 `npm run package:extension` 直接打包，避免重复构建。不要在其他进程仍写入构建目录时运行打包。

打包会将整个 `dist-extension/` 放入 `extension/`，包含 Vite 正常复制的所有公共资源，包括存在时的 `welcome.*`、`room-launcher.js`。校验覆盖清单和项目版本一致性、可选站点权限、必需入口、构建 HTML 的资源引用，以及 `extension-public/` 每个文件与构建产物逐字节一致。必需资源缺失、为空或不一致时失败。包检查会重新生成并对比输出，但不能证明云端网站可用，也不能证明编译代码与所有未提交的源码修改一致。发行前应重新构建。

ZIP 写入器仅使用 Node 内置模块，采用不压缩存储、UTF-8 文件名、固定时间戳、CRC32、SHA-256 与排序路径。拒绝符号链接、非普通文件、不安全或冲突路径、过深目录和超限输入。限制为归档最多 4,096 个文件、单文件 32 MiB、总文件数据 128 MiB、路径 24 段；每个输入目录树遍历也最多 4,096 项。不使用 ZIP64。

参见[发行流程](RELEASE.md)与[本地桌面路线图](LOCAL_DESKTOP_ROADMAP.zh-CN.md)。

开始全新议题时，请移除并重新添加席位，并在提供方页面确认确实处于新对话。当前预览版不宣称所有网站都能自动清空旧上下文；同一席位跨会议的自动新建仍需提供方级验收。
