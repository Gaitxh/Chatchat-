# 本地桌面路线图：当前交付与后续阶段

当前交付是**未签名开发者预览版浏览器扩展包**：预构建文件、双语离线安装页、校验和、版本与提交元数据，以及只上传候选产物的手动 CI。用户无需 Node、Git 或 Rust。独立协商窗口由 Chrome/Edge 承载，使用用户选定的浏览器个人资料；它不是已签名原生桌面应用。

## 第一阶段：浏览器承载的独立窗口

- 通过普通生产构建提供完整 `extension/`，保留欢迎页和窗口启动资源；ZIP 根目录提供 `START-HERE.html`。
- 用户解压到固定位置，在 Chrome/Edge 开发者模式中手动加载 `extension/`，固定图标，选择席位，在同一浏览器个人资料中亲自登录，然后发送提案。
- 浏览器负责运行扩展和账号会话。站点访问需用户明确授权；包不会静默安装，不修改企业策略，不导入登录凭据。
- 每场会议使用新的提供方聊天。已有私人会话不应成为输入。AI 来源平等参与，保留独立首轮、共享快照和不同最终立场。
- 协调与历史在本地，选定 AI 网站的推理仍在云端。合成演示与真实提供方会话分离；窗口可打开或测试通过不代表账号已登录，也不保证任意网站可用。

当前打包测试只验证文件、清单、归档和一致性边界。实际浏览器加载、窗口体验、登录、真实多来源协商和各平台更新行为仍需对应的验证证据。这里的“独立窗口”描述浏览器承载的产品入口，不代表脱离浏览器运行。

更新需先导出重要记录，保留原目录路径和浏览器个人资料，将新文件替换到原 `extension/` 后重新加载。卸载也应先导出；导出记录不等于完整恢复能力。详见[中文安装说明](LOCAL_INSTALL.zh-CN.md)。

## 后续阶段：商店发行

未来可建立 Chrome/Edge 商店审核、隐私披露、发布身份验证与商店更新流程，减少手动加载步骤。当前 ZIP 未经商店签名或审核，也没有自动更新功能。商店可安装性不能替代提供方兼容性验证。

## 后续阶段：已签名原生安装器与浏览器辅助组件

这是**尚未交付**的独立阶段，不应把现有扩展 ZIP 或实验性桌面源码称为已完成的桌面安装器。

需要先明确并实现：

- Windows/macOS/Linux 的安装、卸载、代码签名，以及适用平台的公证和更新签名流程。
- 原生外壳与浏览器辅助组件之间经过认证的最小通信接口、调用方验证、权限提示和消息大小限制。
- 用户明确选择并关联浏览器个人资料；不读取或复制浏览器密码、Cookie、令牌，也不把原生窗口视作已登录证据。
- 保留按站点明确授权、每场会议新聊天、平等席位及合成/真实分离；原生辅助组件不能绕过这些边界。
- 安装器、辅助组件与扩展版本兼容矩阵，导出/恢复设计、升级回滚与数据迁移验证，以及公开的威胁模型和兼容性证据。

旧的原生实验源码在 `apps/desktop/src-tauri/`。当前手动工作流 `.github/workflows/local-package.yml` 只构建扩展包并上传产物，不进行原生打包、签名、公证或发布。未来原生实现需另行交付并验证，不在本次承诺中。
