# 最新轮爆仓时的席位公平公共记忆

ChatChat 要求同一轮里的平等 AI 参与者读取同一份不可变公共快照。但 Provider Prompt 有硬预算，所以公共 Blackboard 不可能无限塞进每一轮 Prompt。

## 这次修掉的隐性偏差

旧策略用等价于 `slice(-maxEvents)` 的方式保护最新一轮。如果“最新一轮本身”就已经超过 12 条事件，那么谁在 Blackboard 批量发布顺序里更靠后，谁的事件就更容易留下来。

Orchestrator 虽然让同轮 Provider 并行回答，但完成后仍会按稳定参与者顺序 materialize/publish 这一批事件。因此“所有下游 Provider 都拿到同一副牌”并不足够：如果这副牌本身因为席位发布顺序偏向后面的参与者，程序上仍然不平等。

## 新的分配规则

如果最新轮不超过预算，行为完全不变，保留整轮。

如果最新轮本身超过预算：

1. 按 `actorId` 把最新轮事件分桶；
2. 每个席位先从自己的最新公开事件开始；
3. 所有仍有事件的席位都先拿到 1 个槽位，任何席位才能拿第 2 个；
4. 再让所有仍有事件的席位各拿第 2 个，然后第 3 个，如此循环；
5. 如果预算无法被活跃席位数整除，只用 `sessionId + round` 派生的稳定旋转分配数学上不可避免的余数；
6. 最终送给 Provider 之前，再把选中的事件恢复成原始 Blackboard 时间顺序。

稳定旋转不读取 Provider 品牌、模型名称、stance、confidence、响应速度、发布时间位置、多数阵营或 Evidence 热度。

## 能保证什么

如果各席位都足够活跃，它们在最新轮硬预算中的事件数最多相差 1。一个只发了 1 条事件的较安静席位，只要预算足够让所有活跃席位至少拿到一个槽，就不会因为其他 AI 话更多而被完全挤掉。

把 A×8 → B×8 → C×8 的整块发布顺序改成 C×8 → A×8 → B×8，在每个 actor 自己的事件顺序不变时，最终选中的 event 集合必须相同。

## 不代表什么

这只是 **memory coverage / 记忆覆盖公平性**。

它不限制每个 AI 在协议上可以发布多少 contribution，不判断哪条发言更重要，不赋予任何模型权威，不改变 convergence / stance alignment，也不声称被选中的事件比被省略的事件更正确。

只要最新轮事件数超过硬预算，就必然有事件被省略。Seat balancing 的目标是让这个不可避免的省略不再系统性奖励 Blackboard 发布顺序靠后的席位。

另外还有一个独立的证据强度问题：仅仅比较 event IDs 仍不足以证明两个 Provider 收到了完全相同的序列化公开 payload。Repair Prompt 也必须证明沿用同一副公共 deck。这会作为下一层独立审计继续实现，而不会和本次分配算法混在一起。
