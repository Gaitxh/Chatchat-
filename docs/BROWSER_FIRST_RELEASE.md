# Browser-First Release Contract

ChatChat's default release evidence is now centered on the Chromium Side Panel.

A normal pull request should prove:

1. shared Council/House/Provider TypeScript is valid;
2. deterministic tests pass;
3. the web demo builds;
4. the Manifest V3 extension builds and validates;
5. the unpacked extension is uploaded as a CI artifact;
6. the real production Side Panel renders in Chromium showcase mode;
7. Summon the House and Community Recipe trust boundaries remain visible and machine-asserted;
8. feature-specific Browser showcases (for example Committee Parliament or Gate B) can add focused evidence workflows without turning the default CI into a desktop matrix.

Desktop/Tauri builds are experimental and manually triggered. They are useful engineering evidence but are no longer required for a Browser-focused pull request to merge.

The first stable browser release still requires user-local Gate B evidence against real Provider tabs. Deterministic showcases prove product behavior and trust boundaries; they do not prove current compatibility with a third-party website.
