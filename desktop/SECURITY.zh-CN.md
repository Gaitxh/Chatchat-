# ChatChat Windows 桌面版 · 安全与可信边界（0.10.1）

## 本地与云端的区别

ChatChat 的界面、会议调度、历史和账号浏览器配置在用户本机运行。**模型推理仍发生在所选择的第三方 AI 网站上。** 用户提交的提案及必要会议上下文会发送给参与的提供方。ChatChat 不要求用户向它填写账号密码或复制 Cookie；网页登录在应用管理的独立 Chromium 配置中由用户完成。

## 发送与会话保护

- 每席拥有自己独立的持久浏览器配置，首次登录后通常可以复用。
- 每次新会议先要求空白新会话，不能把历史聊天直接当作新会议。
- 讨论中会核对席位来源；第一条完整回复后锁定该聊天 URL。发现跳到其他会话即停止自动发送。
- 自动投递前先在本地持久记录操作 ID；如果点击后超时或状态不明确，**不会自动再发一次**。
- 窗口崩溃、会话停止或浏览器异常时，阻止后续轮次继续发送；已发往第三方的消息无法撤回。
- 未就绪或仅能手动打开的席位不参与本轮自动会议。只要两个不同来源已就绪，可由它们先召开会议；界面会显示排除状态。

## 浏览器完整性

0.10.1 对锁定的 Chromium 版本检查四个关键文件的 SHA-256：`chrome.exe`、`chrome.dll`、`resources.pak`、`icudtl.dat`。打包前核验，安装后首次打开模型席位前也核验。发现损坏即拒绝打开自动化浏览器并提示重新安装。这是检测损坏与意外替换的机制，**不能替代 Authenticode 发布者签名**。

应用程序包另外启用了 Electron 在 Windows 的嵌入式 ASAR 完整性验证，并与 onlyLoadAppFromAsar 配对。它在运行时检查嵌入式应用代码包的完整性，能够发现部分篡改或文件损坏；但在发行物尚未签名时，仍不能代替 Windows 代码签名来验证发布者身份。

## 网络出口

软件为受控模型浏览器使用一个仅绑定 `127.0.0.1` 的临时认证 HTTPS CONNECT 通道。每个连接均重新解析域名，要求 DNS 结果全部为公网地址，并直接连接经检查的 IP。回环、内网、特殊地址、明文 HTTP 和其他目的端口均拒绝；Chromium 禁止默认回环绕过、QUIC 以及非代理 WebRTC UDP。

正式桌面版的 WebSocket 使用 Chromium 原生网络栈，经由相同代理出口连接 WSS，而不调用 Playwright 驱动侧 WebSocket 转发。已在本机自签名 TLS/WSS 测试站验证正常收发；这不等于任何真实 Provider 已通过兼容性验收。

本机代理无法启动时会停止自动连接，并提示检查安全软件／防火墙后重启，而不是降级为不经代理的网络访问。

这个通道只转发加密 TLS 字节，不解密、不存档第三方网站的 HTTPS 内容。退出时关闭监听端口与隧道。

**兼容性影响：** 使用本机回调地址、非 HTTPS 资源或特殊网络配置的提供方可能无法登录/访问。此时应明确报错、暂停自动连接，不允许通过关闭安全出口自动降级。

## 仍未完成的发行门槛

1. 未签名开发候选；需要代码签名及受控的正式发行身份。
2. Windows 干净标准用户环境的一键安装、覆盖升级、卸载与异常回滚验收尚未完成。
3. ChatGPT、Claude、DeepSeek、Qwen、Gemini 网页适配仍属实验性，尚无用户账号下的完整端到端多模型协商证明。
4. 网站脚本和模型生成内容仍是不可信输入：DOM 读取证明的是页面观察结果，不证明模型事实正确或无法被网站脚本伪造。用户应检查原始提供方页面与引用。
5. 不承诺第三方网站条款许可无人值守操作。模型网站的登录、访问限制和使用条款独立适用。

## 测试说明

已有自动测试覆盖认证隧道、DNS 回环/私网拒绝、DNS 变更、真实 Chromium 代理回环绕过、关键文件篡改、空新聊天、异常取消、冻结参与者名单和坏历史记录恢复。另在独立的本地 TLS 测试网站上验证了完整消息往返；所有这些都不是第三方真实账号协商验收。

### 自动化发行验收

Windows CI 中额外提供仅能在 GitHub Actions 临时 Windows runner 运行的静默安装、原版覆盖重装、静默卸载和本地数据保留检查。这个 CI 流程必须实际执行通过后才能说「安装器自动化验收通过」；仅编写脚本并不代表已经运行。用户日常 Windows 不会被这项 CI 测试安装任何东西。

## 自愿启动的综合答案安全限制

- 0.10.3 中额外综合答案**不自动调用模型**，必须由用户在刚完成的真实会议中主动点击。每个参加复核的模型追加一次网页 Chat 消息；取消后已发送的请求不可撤回。
- 執笔草稿至少引用两个不同实际模型的会议事件 ID，审查者也须引用真实事件；这些仅证实模型是否引用了既有会议记录，**不是外部事实核验**。
- 审查未通过、格式不正确、网站失败或资料被损坏时，不会生成虚假的“全员通过”标签。历史记录恢复、导出以及崩溃恢复绝不重发请求。

## 用户会议备份与隐私（0.10.3）

一键备份仅从已验证的本地会议存档和非敏感席位书签生成独立 JSON 文件。**不导出** Browser Profile、Cookie、账号登录状态、持久自动发送操作日志或未知的存档元数据字段。备份含问题及模型回复正文，**为明文而非加密**，应妥善保存。导出大小受限且附带 SHA-256 完整性校验；验证功能只读检查选定文件，不自动恢复、更改会议或连接第三方模型。受损存档会被隔离，当前无法安全汇总的会议不会悄悄省略并标记为完整备份。

SHA-256 完整性摘要只能帮助发现意外损坏、普通编辑或文件不一致；任何能修改整个备份的人也可以重新计算该摘要，故不能将它当作加密、身份认证、抗恶意篡改的数字签名。\n
## 受校验的 Windows 离线构建源

当 Windows 构建机无法稳定下载 Electron 时，维护者可以手动指定本机已存在的 Electron ZIP。仅接受与锁定 Electron npm 包版本、Windows x64 文件名和 SHA-256 一致的文件；没有校验的替代二进制会阻止构建。构建后仍验证 Electron ASAR Fuse、Chromium 关键文件及应用运行文件逐项一致。此机制不提供发布者数字签名，也不会在普通用户安装时下载或修改运行时。

## 0.10.4 手动备份恢复权限边界

用户必须先使用原生 Windows 文件选择器选择 JSON，再在 ChatChat 历史面板查看预览，最后通过 Windows 系统确认框授权恢复。**文件路径和内容不暴露给界面 Web 进程**，该进程只接收单次使用、短时有效的恢复令牌与不包含私人正文的数量摘要。确认时主进程会重新读取同一路径，检查文件内容没有改变，并重新验证全部归档。只写入不存在的历史会议；冲突文件一律跳过，不恢复浏览器配置、账号登录或自动发送能力。中途中止尝试回滚已提交文件，重启会清理尚未提交的临时文件。该机制不能证明备份来源可靠：SHA-256 不是防恶意重签的身份认证，请仅导入自己的可信备份。


## 0.10.5：自动适配的能力诚实标记

自动实验性适配器和手动网站席位分开显示。MiniMax、小米 MiMo、自定义网站被标记为手动席位，允许用户手动浏览但不会被自动发送提案，也不会被当作实际参会模型。未识别出网页聊天控件不证明用户未登录，系统会标记页面需要处理而不是暗示必须重新输入密码。五种实验性模型网站的模拟 DOM 测试只验证本地 Chromium 收发边界，未登录真实账号，也不代表网站条款允许自动控制。
