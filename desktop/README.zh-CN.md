# ChatChat Windows 桌面版

这是独立桌面多模型协商软件，不是浏览器扩展、PWA 或网页快捷方式。

## 安装与第一次使用

取得 `ChatChat-Setup-0.10.7-x64.exe` 后，双击即可安装到当前 Windows 用户目录并打开 ChatChat。安装包自带应用和完整浏览器运行环境，不要求 Node.js、Python、Git、API Key、Chrome 扩展或开发者模式。安装过程不下载额外运行环境；连接在线 AI 仍需网络。

在软件里点空席位的 **＋**，选择模型网站，在弹出的专用浏览器窗口登录。登录后软件自动检查页面，必要时可手动点“检查”。至少两个已就绪的不同来源入席后，在底部输入问题并开始讨论。上轮聊天不会直接当作新会议；新会议会创建新页面并检查空对话。

首次在本软件使用某个网站通常需要登录一次。本软件的登录配置与日常 Chrome/Edge 独立，不读取或复制日常浏览器的 Cookie。已登录的专用配置可以继续使用，除非网站要求重新登录或验证。

## 这份预览的范围

目标系统是 Windows 10/11 x64。当前打包产物是未签名的开发预览，不应当作已验收的正式发行版；Windows 可能显示未知发布者警告。不要关闭系统安全防护。正式发布仍需要发布者签名及干净 Windows 环境的安装、升级和卸载验收。

本版本提供独立桌面界面、环绕席位、底部提案、模型网站窗口、自动登录状态检查、受控多轮协商、停止、历史回放和 Markdown 导出。协议保留每个模型自己的最终立场与异议，不将多数同意等同于正确，也没有宣称实现了已经过全部模型复核的单一综合答案。

ChatGPT、Claude、DeepSeek、Qwen、Gemini 的自动连接配方是实验性的，尚无本轮真实账号端到端验收。网站变化、登录限制或网页结构不明确时会停止，不会假装就绪。MiniMax、小米 MiMo 和未知自定义网站目前允许打开作为待适配席位，但不能直接加入自动讨论；界面会明确标注。不能承诺任意网站都允许被第三方自动操作。

本版新增一条本机认证 HTTPS 出站通道，使用经验证的公网 IP 连接网站；发现内网跳转或浏览器文件损坏会直接阻止自动发送。对使用本机回调或特殊网络规则的网页，可能需要等待兼容适配，不能关闭安全保护强行连接。

详细安全边界和剩余限制：[Windows 桌面安全说明](SECURITY.zh-CN.md)。

## 可选的模型交叉复核答案（0.10.3 新增）

普通会议会像以前一样记录每位模型的完整最终立场，**不会自动额外扣除模型网站额度**。会议结束、至少两位真实参会模型仍然可用时，可以在中央「各方立场」页面**主动点击「生成复核答案」**。这项操作会在原会议的模型 Chat 中增加一次执笔请求和每位审查者各一次的复核请求；最多等于本次实际参加的模型数量，不能把普通会议结束视作已经自动产生「最佳答案」。

平台轮流选择一名原始参会模型起草面向用户的答案，必须引用至少两个不同模型的真实会议发言 ID。其余实际可用参会模型各自审查草稿；缺失引用、格式不正确、审查反对或超时，都不会被算成赞成。只有所有被邀请的审查者实际完成并赞成，才显示「全部审查通过（不等于事实正确）」；反对和失败始终保留。

点击引文可跳转至原始发言。综合草稿、审查意见与原始最终立场一起本地保存并可导出 Markdown。**历史回放、应用重启和取消操作不会重新发送综合答案请求**。软件意外关闭时会将未完成的复核标记为中断，原会议报告保持不变。网页账号是否支持该流程仍需真人登录后的提供方级验收。

## 本地会议备份与安全校验（0.10.3 新增）

现在打开「历史会议」即可点击 **「备份全部会议」**，手动选定文件位置，一次性导出所有已保存的有效会议、原始模型观点、复核草稿、审查回执，以及简单的席位书签。备份为明文 JSON，包含真实问题和模型回复等私人内容；**不包含**任何 Chromium 登录会话、Cookie、浏览器用户资料、模型授权资料或自动化操作日志。

导出文件带 SHA-256 完整性校验。点击 **「验证备份文件」** 可以只读检查文件是否完整及其中包含多少场会议；不会访问模型网站，不会覆盖或导入当前记录。超过大小上限或受损的会议归档不会被误报成成功的完整备份，用户仍可逐项导出有效会议。

**0.10.4 已支持经过校验的本地会议手动恢复。** 在「历史会议」中点「预览恢复」，选择先前导出的 JSON 备份。软件会在本机验证内容并显示可新增、已存在和源备份可能遗漏的会议数量；再点击「确认恢复历史」，由 Windows 原生确认框二次授权。只会恢复原始历史归档，**不会覆盖同 ID 的会议、添加模型席位、恢复 Cookie、启动模型 Chat 或发出新模型请求**。账号在新电脑仍需要重新登录。若导入被意外中断，已有记录不会被覆盖，再次选择同一备份会自动跳过已导入会议。恢复仅能识别 ChatChat 官方结构的备份，不保证识别任意聊天平台的手工 JSON。

另外修复：会议结束后，用户只检查某个未就绪席位不会再关闭「生成复核答案」入口。重新打开、添加或移除席位等有可能改变实际聊天身份的操作仍会停止后续旧会话自动发送权限。

## 0.10.4：导入前预览及安全恢复

- 备份文件先通过大小、SHA-256 和归档字段约束检查，不能直接把路径、Cookie 或网页内容传给恢复引擎。
- 预览只提供摘要和一个**单次、限时的令牌**；选择恢复后会再次读取文件并比对内容摘要。如果预览后文件变化、会议记录发生冲突或令牌过期，必须重新预览。
- 对缺失的历史文件采用同目录预写入和**不会覆盖目标的硬链接**提交；异常时尽力回滚，退出时等待操作收尾。意外断电留下的中间临时文件会在下次启动时清理。少量已经写入的历史可以通过再次导入同一备份安全补齐。
- 当前暂不恢复席位偏好，也不会复用其他电脑的登录会话。恢复摘要会明确写明跳过的会议和席位书签。
- SHA-256 是普通完整性检查，**不是备份来源的数字签名或文件加密**。只能从自己信任的来源恢复备份文件。

## 维护者：网络不稳定时的 Windows 离线打包

本功能仅用于**构建**，普通用户安装 ChatChat 时不需要 Electron 下载、npm 或环境变量。在 Windows 开发机已经通过可信软件包获得与当前锁定版本完全相同的 Electron ZIP 后，可使用：

PowerShell：
    $env:CHATCHAT_ELECTRON_DIST = 'C:\\本地缓存\\electron-v45.0.0-win32-x64.zip'
    npm run package:win

构建器只接受文件名、版本、Windows x64 架构和 SHA-256 均与项目锁定 Electron npm 包内 checksum 清单一致的压缩包。错误文件会被拒绝，不会绕过 Chromium 文件检查、ASAR 代码包完整性检查或 Windows 打包校验。未指定该变量时，CI 仍使用默认上游获取流程。

## 数据与控制

会议调度、记录和账号浏览器配置保存在本机应用目录。模型推理由所选网站处理，提案及讨论上下文会发送给它们。没有额外的 ChatChat 云端中转服务。

安装仅作用于当前用户，不修改浏览器企业策略。卸载默认保留账号配置和会议历史；重要会议可先导出。更新和修复前关闭 ChatChat。不要把应用数据目录整体发送给别人，其中可能含登录状态。

停止会阻断后续发送，已交给提供方的请求不保证能撤回。不确定某次发送是否成功时，不自动重复投递。退出会关闭软件管理的浏览器，不影响用户日常浏览器。

## 验证说明

已在 Windows 11 x64 的干净临时工作目录通过 146 项桌面自动化测试（含捆绑 Chromium、真实浏览器受控页面交互、会话锁定、历史异常隔离和取消边界），并由 Windows 原生工具链生成 NSIS 安装程序。**这不是实机安装／升级／卸载验收，也不是线上 Provider 回答测试。** 受控网页只用于验证界面、消息关联、隔离新会话、去重和取消等行为。

## 开发者构建

本节不是普通用户的安装步骤。开发者在仓库根目录准备依赖并编译 core，在 desktop 目录使用锁定的依赖和脚本。

```text
仓库根：npm ci
桌面目录：npm ci
桌面目录：npm test
桌面目录：npm run package:win
```

`package:win` 从固定 SHA256 资源构建自包含安装包；生产发布需要在安全凭据体系中配置签名。正式候选只使用 Windows 上的 electron-builder NSIS 打包路径，避免不同安装器产生重复的卸载项；Linux 上的交叉打包仅保留为历史研究证据，不作为分发方式。


## 手动席位与实验性自动席位的区别（0.10.5）

添加模型后，席位会明确显示它的实际能力：

- **已就绪**：只说明实验性网页自动适配识别了可用的新聊天控件，正式发送前仍会重新验证；不代表模型回答正确或官方承诺兼容。
- **手动席位**：MiniMax、小米 MiMo 和尚未适配的公共网站，允许用户在独立浏览器中自行登录、使用网站，但 ChatChat 不会控制其聊天输入框，也不会把它算作自动协商参会者。这不是登录失败或系统故障。
- **需要登录／需要处理**：可能是网站要求登录、账号验证、页面改版或者消息状态异常；用户可以查看席位诊断，而系统不会自动重复发送可能已经送达的消息。

两位不同来源的已就绪模型即可进行自动协商；其他手动或暂未就绪席位保留在会议室，不影响它们之间的讨论。

## 0.10.6：安装包实际载荷核验与隔离 CI 门槛

维护者现在可在 Windows 上运行 npm run package:win，构建器不再只验证 win-unpacked 构建目录：它还会**实际解压**最终生成的 NSIS Setup.exe 内部的 app-64.7z，逐文件比较哈希、文件数、相对路径及内容，核验随安装程序分发的 Chromium 关键文件。成功后生成 release/NSIS-PAYLOAD-VERIFICATION.json。普通用户只需双击安装文件，不需要自行进行任何解压或开发操作。

此关卡**不会运行安装器，也不会读写 Windows 注册表或用户安装目录**。真正的安装、同版本重装与卸载仍由独立的 GitHub 托管临时 Windows runner 负责；对应脚本已增加托管 Runner 身份限制、安装进程等待超时和精确的程序清理范围。脚本本身和负向安全测试通过不代表 GitHub CI 已实际执行。跨版本升级、签名和真实网站登录另需验收。

## 0.10.7：更保守地判断模型网页回答完成

自动发送后，ChatChat 不再只凭“复制回答”按钮出现、文本短暂停顿就当作回答完成。正式使用采用至少约 **5 秒**连续稳定的回答观察窗口，还会核对网页最新显示的用户消息是否等于当前发往该模型的提案；若网站对文字进行格式化、脚本变更消息或出现其他聊天内容，宁可停止自动采信并标为“不确定”，也不会将错误会话当作已验证回答。**不确定操作不会自动重发。**

浏览器控件的稳定观察仍只是网页自动化启发式，**无法百分百证明第三方模型流式生成已经终止**。这是实验性能力；第三方网站的 DOM 和完成标记可能改变，导致接入失败。相比先前版本，等待时间会变长，这是为了减少把不完整回复传给其他模型的风险。请在原模型聊天页面检查重要回答。

## 0.10.7：通过草稿 PR 执行临时 Windows 安装器 CI

维护者可对 main 发起只含 Windows 桌面相关变更的 Pull Request，Windows CI 将通过 GitHub 托管的临时 Windows runner 自动运行受控模拟模型测试、构建后解包逐文件检查，以及真正的安装／同版本重装／卸载与本地数据保留验收。此 CI 没有写权限，不接触签名密钥或个人模型登录资料。草稿 PR **不会自动合并发布**。

此 CI 通过只证明在 GitHub 临时机器上的对应操作通过，并不证明消费者电脑上的代码签名、真实账号兼容性或完整跨版本升级。


### 临时 Windows runner 的桌面启动诊断边界

GitHub 托管的 Windows runner 可能运行于非交互式桌面会话。真正的安装／同版本重装／卸载、数据保留和安装包校验是**必须通过**的 CI 关卡；对 Electron 原生窗口的额外测试改为隔离的无界面诊断项目，并清楚保留其通过或失败状态。该诊断不应阻止安装测试，也不能在失败时被报告成通过。开发机仍以独立临时配置实测 Electron 桌面窗口。模拟备份恢复测试现在等待事务落盘、工作状态退出后才判定成功，避免读取原子提交过程中的中间状态。


### 0.10.7：实际安装器卸载辅助进程的有界验收

GitHub 托管 Windows runner 已执行真正的静默安装、同版本重装和卸载测试。首轮安装器验收在卸载程序启动后立即检查 HKCU 卸载项，发现卸载注册表项还存在；该轮测试**失败**，不能据此判断安装器成功。

NSIS 可能启动临时卸载辅助进程（Windows runner 日志中出现 Un_A），使卸载启动程序先退出而清理继续运行。新的必选验收步骤会在不超过 120 秒的时限内检查 HKCU 卸载项和主程序文件，二者均消失才算完成；否则打印受限的卸载项标识并失败。初次安装与同版本重装还核对安装目录中的 ChatChat.exe、app.asar 及 Chromium 核心文件 SHA-256 与已验证发行文件相同。此前在本地工作电脑上没有运行 Setup/Uninstall，此类真正的安装操作仍只允许在 GitHub 托管临时 runner 执行。

**注意：脚本和测试通过不代表 GitHub 远程验收通过，必须以对应 Actions 运行日志为准。** 跨版本升级、代码签名、真实账号兼容仍未验收。
